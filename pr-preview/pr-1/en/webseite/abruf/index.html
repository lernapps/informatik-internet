Exercise

Ben has typed in the URL. What does his phone need before it can send the request to the web server?

  • the IP address of the web server right answer

    Routers only read numbers. So the phone first asks DNS for the address.

  • the page itself

    The page only comes as the response. First the request has to reach the server.

  • the file path on Ben's phone

    The path in the URL points to the web server, not to Ben's phone.

Without an IP address no router knows where the request should go. That is why DNS comes first.

Try it: the whole journey

On this map you see everything together: Ben's phone, routers, the purple DNS server and the orange web server. Press Next step until the page reaches Ben. Look out for steps 1 to 6 in the list.

Map 8: the whole journey of the trip page

✉ The packet says: to 203.0.113.53, from 192.0.2.25: question about www.schule.example

Ben has typed in the URL. Press “Next step”.

Map 8: Ben's phone (192.0.2.25) is joined through Ben's router to router 1. Router 1 has the DNS server (203.0.113.53) and the school router with the web server (198.51.100.7).

  1. Step 1: the browser reads the URL. Step 2: it asks the DNS server for the IP address of www.schule.example.
  2. Routers pass the question on …
  3. … to the DNS server.
  4. The DNS server answers: 198.51.100.7.
  5. The answer travels back …
  6. … to Ben's phone.
  7. Step 3: the browser sends the request by HTTPS: GET /klasse-7b/ausflug.html. With HTTPS the content is encrypted; routers only read the addresses.
  8. Routers pass the request on …
  9. … into the school network …
  10. Step 4: the web server looks for the file ausflug.html in the folder klasse-7b.
  11. Step 5: it answers 200 OK and sends a copy of the page, in many packets.
  12. Routers pass the response on …
  13. … back to Ben …
  14. Step 6: the browser puts the packets together and shows the page. For each photo on it, it sends another request.

Remember

The page does not move away from the web server. It sends a copy. That is why many phones can load the same page at the same time.

Example: finding the fault

Two messages, two steps

  • “Server not found”: step 2 went wrong. DNS does not know the name, for example because of a typo in the domain name.
  • “404 Not Found”: the web server answered, steps 1 to 3 worked. In step 4 it did not find the file, for example because of a typo in the path.

Give each entry its place: 1 for the first.

Right answer: 1. The browser reads the URL., 2. The browser asks DNS for the IP address., 3. The browser sends the request to this address., 4. The web server looks for the file for the path., 5. The web server sends a copy as its response., 6. The browser shows the page.

First translate the name into a number, then ask, then answer. Routers pass every packet on along the way.

What you can do now:

  • The internet is a network of networks; routers pass packets on.
  • The client asks, the server answers.
  • Every device in a network needs an IP address; DNS translates names into addresses.
  • A URL has a protocol, a domain name and a path.
  • The web, email and chat are services with their own protocols.
  • You can explain how a web page is loaded in six steps.
